# Menu-First Boot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Boot into the menu with no level behind it, let the player start and leave levels, and move menu layout out of code and into prefabs authored in the Unity editor.

**Architecture:** The bootstrap splits into what always exists (camera, shell, input, sources, manifest) and what a level needs (driver, world, views, overlay, tuning panel, editor) — the latter under one root object created on play and destroyed on quit. Menu options and level ordering become tested plain C#; the view only draws and dispatches. Screen layout comes from an optional prefab, with the current code-authored positions as the fallback when no prefab exists.

**Tech Stack:** Unity 6000.2.6f2, C#, `Resources.Load`, NUnit EditMode tests. No new packages.

**Spec:** `docs/superpowers/specs/2026-08-25-menu-first-boot-design.md`

## Global Constraints

From `CLAUDE.md` and the spec. Every task's requirements implicitly include these.

- **Determinism (GDD §6.1) is non-negotiable.** Simulation runs in `FixedUpdate` at 60 Hz. No `Time.deltaTime`, no `Random`, no wall-clock in simulation code. Iterating an unordered collection where order affects the result is a defect. **This plan adds no simulation state**, so the replay-equality test needs no changes — if that stops being true, the new state joins `SimSnapshot` in the same commit.
- **`.unity`, `.prefab` and `.asset` files:** still forbidden for sim, levels, tuning and gameplay views. Task 9 scopes this rule for shell presentation. **No task in this plan authors a prefab** — Task 7 makes prefabs *optional*, and the author creates them by hand in the editor afterwards.
- **Do not modify anything in `ProjectSettings/` without asking first.**
- **No `using UnityEditor;` outside test assemblies**, and never under `Assets/_Project/Scripts/LevelEditor/`.
- **Rules live in tested plain C# classes; views only draw.** `ShellView` and `SimBootstrap` have no EditMode tests and cannot get them. Anything that is a *decision* belongs in `Shell/` or `Sim/`.
- **Rendering:** 640 × 360, integer scaling, 20 px tiles. 1 world unit = 1 tile = 20 px.
- **Reserved keys.** Gameplay: `Space W A D J R Esc`, arrows, left Shift. Editor: `1 2 3 5 P U G H T L Delete`, `Ctrl+S/Z/Y`. New bindings avoid all of them.
- **Run `./test.sh` before reporting any task complete.** Exit 0 means every test passed. Say so explicitly if it could not run, and why.
- **The Unity Editor must be closed** for `./test.sh` — batch mode takes an exclusive lock on `Library/`. If a run hangs beyond ~2 minutes, stop and ask. Never retry in a loop, never delete `Library/`.
- **Single-test runs:** `./test.sh -testFilter "KeepyUppy.SimTests.ClassName"`.
- **`.meta` files** are generated by Unity's next run, which includes a batch-mode test run. Run the tests before `git add`.

        /// <summary>
        /// The level after this one in the same world, or null.
        ///
        /// Deliberately does not roll into the next world at a world's end: crossing worlds
        /// is a progression question that belongs with save data (GDD 15), not with "what is
        /// the next room". An unlisted id — a draft — has no answer either.
        /// </summary>
        public string NextAfter(string id)
        {
            LevelWorld world = WorldOf(id);
            if (world == null) return null;

            int slot = SlotOf(id);
            int next = slot + 1;

            return next >= 0 && next < world.levels.Length ? world.levels[next] : null;
        }

```csharp
using UnityEngine;

namespace KeepyUppy.Shell
{
    /// <summary>What a menu option does when confirmed. The view maps these to calls.</summary>
    public enum ShellAction
    {
        Resume,
        Restart,
        NextLevel,
        Retry,
        QuitToLevels,
    }

    /// <summary>
    /// A single column of options and a cursor over them, shared by the pause and results
    /// screens — they differ only in which options they offer.
    ///
    /// A rule, not drawing, so it lives here and is tested. The cursor clamps rather than
    /// wraps, matching LevelSelectModel: wrapping a three-item list reads as a jump.
    /// </summary>
    public sealed class OptionMenu
    {
        ShellAction[] _options;

        public OptionMenu(params ShellAction[] options)
        {
            SetOptions(options);
        }

        public int Cursor { get; private set; }

        public int Count => _options.Length;

        /// <summary>Falls back to Resume when empty — a harmless default rather than a throw.</summary>
        public ShellAction Selected => Count == 0 ? ShellAction.Resume : _options[Cursor];

        public ShellAction At(int index) => _options[index];

        /// <summary>
        /// Replaces the options and returns the cursor to the top. Results offers Next only
        /// when a next level exists, so its list changes between rooms and a kept cursor
        /// could point past the end of a shorter one.
        /// </summary>
        public void SetOptions(params ShellAction[] options)
        {
            _options = options ?? new ShellAction[0];
            Cursor = 0;
        }

        /// <summary>
        /// Moves one step. Only the vertical axis matters — these menus are a single column.
        /// Vector2Int.down is (0,-1) and the list reads top to bottom, so down is the next
        /// entry; the same inversion LevelSelectModel documents.
        /// </summary>
        public void Move(Vector2Int step)
        {
            if (Count == 0 || step.y == 0) return;

            Cursor = Mathf.Clamp(Cursor - step.y, 0, Count - 1);
        }

        /// <summary>The text the view draws for an option.</summary>
        public static string Label(ShellAction action)
        {
            switch (action)
            {
                case ShellAction.Resume:       return "RESUME";
                case ShellAction.Restart:      return "RESTART";
                case ShellAction.NextLevel:    return "NEXT LEVEL";
                case ShellAction.Retry:        return "RETRY";
                case ShellAction.QuitToLevels: return "QUIT TO LEVELS";
                default:                       return "?";
            }
        }
    }
}
```

        public LevelSession Session { get; private set; }

        /// <summary>
        /// Builds a level and everything it needs. Returns null if the level cannot be read,
        /// leaving the caller on the menu rather than in a half-built room.
        /// </summary>
        public LevelSession StartLevel(string id)
        {
            EndLevel();

            if (!_levelSource.TryLoad(id, out LevelData level))
            {
                Debug.LogWarning($"[level] '{id}' could not be loaded");
                return null;
            }

            Session = LevelSession.Create(transform, level, id, _tuningProfile, _tuningSource, Seed);
            return Session;

        public void EndLevel()
        {
            if (Session == null) return;

            Destroy(Session.gameObject);
            Session = null;
        }

- [ ] **Step 2: Dispatch the actions**

```csharp
        void Perform(ShellAction action)
        {
            switch (action)
            {
                case ShellAction.Resume:
                    _stack.Back();
                    break;

                case ShellAction.Restart:
                case ShellAction.Retry:
                    Bootstrap.Session?.Restart();
                    _stack.ResetWin();
                    _stack.Go(AppScreen.Playing);
                    break;

                case ShellAction.NextLevel:
                    StartLevel(_index.NextAfter(Bootstrap.Session?.LevelId));
                    break;

                case ShellAction.QuitToLevels:
                    Bootstrap.EndLevel();
                    _stack.QuitToLevels();
                    break;
            }
        }
```

`Retry` and `Restart` both reset the win edge, for the same reason `QuitToLevels` does: the room is about to be winnable again and its previous win must not count as still-true.
